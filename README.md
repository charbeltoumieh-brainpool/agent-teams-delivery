# Agent Teams — Ticket Delivery Pipeline

A 6-teammate agent team that **fetches GitHub tickets, implements them, QAs them, and ships them**.

## Pipeline (roles)

| Stage | Teammate | Responsibility |
|---|---|---|
| 1. Triage | `ticket-triage` | Fetch open tickets from GitHub, normalize them into `backlog/`, rank by priority, mark `status/triage` |
| 2. Implement | `dev-core` | Claim an approved ticket, build it on a `feat/<issue>-<slug>` branch, open a draft PR |
| 3. QA | `qa-engineer` | Independently verify on the branch, write `qa/<issue>.report.md`, PASS/FAIL, never self-review |
| 4. Release | `release-manager` | After QA PASS, label `status/verified`, merge, close the ticket, tag |
| 5. Verify | `verifier` | Adversarial review of every claim; re-runs the evidence; can send work back |
| 6. Report | `scrum-reporter` | Board + dashboard rollup in `reports/`, keeps the comms map |

## Ticket source

GitHub via the `gh` CLI (authenticated). Repo: `charbeltoumieh-brainpool/agent-teams-delivery`.

```powershell
gh issue list --repo charbeltoumieh-brainpool/agent-teams-delivery --state open
```

## Demo target

`delivery/tiny-strings` — a zero-dependency Node module with a real test suite (`node test/run-tests.js`).
Tickets ask for genuine features/bugfixes in this module so the pipeline produces real diffs.

## Definition of Done (per ticket)

1. Code change on a feature branch, tests added/updated.
2. `node test/run-tests.js` passes locally (QA re-runs it independently).
3. PR opened, linked to the ticket (`Closes #<n>`).
4. QA report exists with PASS verdict and evidence commands.
5. Verifier countersigns the QA report.
6. Merged, ticket closed, `status/verified` label applied.
